# Actualización del workspace a Python 3.14 — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Subir todo el workspace uv (raíz, Api, PiSystemAgent, PiRobotDriver) a Python 3.14 como versión mínima, en el host y en todas las imágenes.

**Architecture:** El workspace comparte un único `uv.lock`; su `requires-python` es la intersección de los `requires-python` de los miembros. Subir los cuatro `pyproject.toml` a `>=3.14` y re-lockear solo poda la rama `< 3.14` del lock: no cambia versiones de paquetes. Las imágenes de PiSystemAgent y PiRobotDriver ya usan 3.14 (`ros:lyrical`); la de la Api usa 3.13 y hay que cambiarla. Un `.python-version` en la raíz hace que `uv` use 3.14 en el host.

**Tech Stack:** uv (workspace + lock), Python 3.14, Podman/Docker, FastAPI (Api), rclpy lyrical (Pi).

**Spec:** No hay un documento de spec. La decisión salió de la revisión del 2026-10-12, hallazgo #1 de `tmp/findings.md`: con 3.14 (PEP 649), las anotaciones de `Executor` bajo `TYPE_CHECKING` en `services/PiSystemAgent/controller/main.py` dejan de lanzar `NameError` al importar. La evidencia previa a este plan está en la sección "Evidencia".

## Global Constraints

- Versión mínima: `requires-python = ">=3.14"` en `pyproject.toml` (raíz), `services/Api/pyproject.toml`, `services/PiSystemAgent/pyproject.toml` y `services/PiRobotDriver/pyproject.toml`.
- `.python-version` en la raíz con el contenido `3.14`.
- Imágenes de la Api: builder `ghcr.io/astral-sh/uv:python3.14-bookworm-slim` y runtime `docker.io/library/python:3.14-slim-bookworm`. Las dos tienen que usar la misma versión menor (el venv del builder se copia al runtime).
- El relock **no** debe cambiar la versión de ningún paquete; solo el encabezado del lock.
- Documentación en español; los README van en dos versiones (`README.md` en inglés y `README.es.md` en español), referenciándose entre sí (CLAUDE.md raíz).
- El modo demo tiene que seguir funcionando sin hardware ni ROS (CLAUDE.md raíz, "Modo demo").
- No tocar `ros_tryouts/` (CLAUDE.md raíz).
- **Fuera de alcance:** el deploy a producción (`quadlets/deploy.sh` contra el servidor) y a la Pi. Este plan termina con las imágenes compiladas y verificadas localmente. Desplegar requiere la confirmación explícita del usuario.

## Review Focus

1. **Relock con cambios de versión inesperados:** si `uv lock` sube o baja algún paquete, el cambio deja de ser "solo versión de Python". Lo comprueba el Task 1, Step 5, que exige un diff sin líneas `version =`.
2. **Venv del host que sigue en 3.13:** si `.venv` no se recrea, los tests corren en 3.13 y "pasan" sin probar nada. Lo comprueba el Task 1, Step 7, que exige `Python 3.14` en la salida.
3. **Imagen de la Api con stages de distinta versión:** si builder y runtime difieren, el venv copiado apunta a un intérprete inexistente y el contenedor no arranca. Lo comprueba el Task 2, Step 3, que ejecuta `python --version` e importa `src.server` dentro de la imagen final.
4. **Modo demo en el host (el motivo del cambio):** `import controller.main` sin rclpy tiene que funcionar en 3.14. Lo pinea el test de regresión del Task 1, Steps 1-2 y 8.
5. **`pylock.toml` regenerado distinto del original:** no tiene consumidores conocidos (`grep` sin usos), pero un export con otras opciones cambiaría el conjunto de paquetes. Lo comprueba el Task 1, Step 6, que compara la lista de nombres de paquetes antes y después.

```python
"""Regresión: `controller.main` debe importarse sin ROS (modo demo en el host).

En Python < 3.14 fallaba con `NameError: name 'Executor' is not defined`, porque
las anotaciones de `Executor` (importado sólo bajo TYPE_CHECKING) se evaluaban
al definir las funciones. Con 3.14 (PEP 649) se evalúan de forma diferida.
"""
import os
import subprocess
import sys
from pathlib import Path

PKG_ROOT = Path(__file__).resolve().parents[2]  # services/PiSystemAgent


def test_main_se_importa_sin_ros():
    env = os.environ | {
        "SERVER_URL": "http://127.0.0.1:9/m2m/robot/",
        "ARDUINO_PORT": "/dev/null",
    }
    result = subprocess.run(
        [sys.executable, "-c", "import controller.main"],
        cwd=PKG_ROOT,
        env=env,
        capture_output=True,
        text=True,
        timeout=30,
    )
    assert result.returncode == 0, result.stderr
```
